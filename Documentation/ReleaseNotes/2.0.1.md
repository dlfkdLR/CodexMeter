# CodexMeter 2.0.1

Follow-ups to the 2.0 notch, and the last two provider rings.

## What changed

### Token usage stays front and centre

2.0 moved the token accounting into Settings ▸ Usage, which risked burying the
thing CodexMeter is *for*. This pulls it forward:

- The status-bar menu leads with **Token Usage…** (⌘U).
- The notch's right-click menu has it too.
- Reopening the app (Finder/Dock) opens the Usage view.
- The Settings window opens on the Usage pane by default.
- The notch tooltip shows today's local token total for Codex and Claude beside
  the limit rings — the "how much have I used" the ring's percentage doesn't
  give.

### Two more provider rings

- **Antigravity** — Gemini usage read from Antigravity's own local language
  server (the IDE or the `agy` CLI must be running; that is where the number
  lives). Google refuses a third-party client, so this is the door Antigravity
  itself uses.
- The **Ollama Cloud** ring now works from a key pasted into
  **Settings ▸ Notch ▸ Ollama Cloud** (kept in the login Keychain), not only
  from `OLLAMA_API_KEY`.

### Cursor

When the Cursor editor has no session, the notch falls back to the
`cursor-agent login` session.

## Fixed

- **The notch's provider polling ran even while the notch was hidden**, and a
  feedback loop (each fetch wrote its cache to `UserDefaults`, which
  `AccountLimitStore` reacted to) had it re-fetching every borrowed-credential
  provider several times a second. It now runs only while the notch is on
  screen, keyed on real limit changes.
- The notch's right-click menu and a couple of settings strings still said
  "Codenotch".
- The status-bar item now installs from `applicationWillFinishLaunching` too — a
  `Settings`-only app does not reliably reach `applicationDidFinishLaunching`.

## Verification

- 589 automated tests, 0 failures (9 environment-integration tests skipped).
- `swift build` with zero warnings and zero errors.
- Universal 2 build for Apple silicon and Intel Macs running macOS 14 or later.
- Verified on a release build: hidden notch does no provider polling; the status
  item installs on launch.
- Ad-hoc signed, not Apple-notarized. SHA-256 protects the first download;
  Sparkle authenticates later updates with Ed25519 signatures.


```bash
xattr -dr com.apple.quarantine /Applications/CodexMeter.app

```

## First direct-download launch

Download `CodexMeter-2.0.1.dmg` and `SHA256SUMS.txt` into the same folder and
verify the checksum before opening:

```bash
cd ~/Downloads
grep ' CodexMeter-2.0.1.dmg$' SHA256SUMS.txt | shasum -a 256 -c -
open CodexMeter-2.0.1.dmg
```

Only after `OK`, copy `CodexMeter.app` to Applications and use the app-scoped
quarantine command above.
